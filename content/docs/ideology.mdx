## What every library follows

- **One problem, solved well.** A library that grows a second purpose becomes two libraries.
- **A small API.** Fewer functions that compose beat many that overlap. If something can be
  built from what exists, it is not added.
- **No surprises.** Nothing yields unless it says so, nothing is created behind your back, and
  everything that can be connected can be disconnected.
- **Cleanup is part of the design.** Anything that owns something gives you a way to clean it
  up, through a Connection or a Void.
- **Fast where it matters.** Hot paths, like firing a signal or spawning a thread, reuse what
  they can instead of allocating on every call.
- **Typed first.** Types are written for the new solver and are part of the API, not an
  afterthought.

## The code is written by people

The code of the libraries is not written by AI.

Libraries are foundations: other code builds on them and trusts them without reading them.
Code generated by AI looks right more often than it is right. It gets the common case and
misses what matters in a library:

- **Subtle bugs.** Threads that yield, connections that outlive their owner, cleanup that runs
  twice. These are exactly the mistakes generated code makes and that tests rarely catch.
- **No design behind it.** An API is a set of decisions: what to leave out, what to name
  things, how pieces fit together. Generated code averages what it has seen instead of
  deciding.
- **Nobody owns it.** Every line of a library has to be understood by the person who
  maintains it. Code nobody wrote is code nobody understands.

## Where AI is used

AI is a tool, used where its mistakes are cheap to see and fix:

- **Documentation and comments.** Rewording, fixing typos, and making explanations clearer.
  The code they describe is still checked by hand.
- **The foundations around the libraries, in reason.** Scaffolding, scripts, CI and this site.
  Anything AI writes there is reviewed like any other change, and it never touches the logic
  of a library.

## Contributions

The same rules apply to everyone. Changes to a library's code must be written by you, and you
must be able to explain every line of them. Pull requests whose library code was generated by
AI are closed. Using AI to improve docs or comments is fine.
