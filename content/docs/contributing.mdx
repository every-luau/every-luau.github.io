## Setup

every library lives in the [every](https://github.com/every-luau/every) repository. you need
[lune](https://github.com/lune-org/lune), pinned in its `ember.toml`, and
[just](https://github.com/casey/just), which runs every command below

<Files>
  <Folder name="every" defaultOpen>
    <Folder name="libraries" defaultOpen>
      <Folder name="Thread" />
      <Folder name="Signal" />
      <Folder name="..." />
    </Folder>
    <Folder name="template" />
    <Folder name="scripts" />
    <File name="justfile" />
  </Folder>
</Files>

- `libraries` has one folder per library, and each one is its own package
- `template` is what `just new` copies to create a library
- `scripts` has the lune scripts behind the `just` commands

## Layout of a library

<Files>
  <Folder name="Thread" defaultOpen>
    <Folder name="src" defaultOpen>
      <File name="init.luau" />
    </Folder>
    <Folder name="tests">
      <File name="init.spec.luau" />
    </Folder>
    <Folder name="examples" />
    <File name="fumablox.toml" />
    <File name="ember.toml" />
    <File name="default.project.json" />
  </Folder>
</Files>

| File | What it is for |
| --- | --- |
| `src` | the library itself |
| `tests` | its [lest](https://github.com/lest-luau/lest) specs, one test per public function at least |
| `examples` | scripts shown at the bottom of the library's page |
| `fumablox.toml` | its `title` and `description` on this site, and how its API reference is generated |
| `ember.toml` | the package on ember: its name, version and dependencies |

libraries require each other as siblings (`script.Parent.Thread`), the way package managers
install them. when you use another library, add it to the dependencies in your library's
`ember.toml`

## Commands

```bash
just new Name              # create libraries/Name from the template
just test Signal           # run a library's tests
just test-all              # run every library's tests
just docs Signal           # check its documentation comments
just sourcemap             # let luau-lsp resolve requires between libraries
just site                  # generate the docs and run this site locally
just versions              # every library's version
just bump Signal minor     # bump its version
just release Signal patch  # bump, test and publish to ember
```

## Documenting

[fumablox](https://github.com/metricrb/fumablox) generates the API reference from Moonwave
comments, and only what has a comment shows up:

```lua
--[=[
	@class Thread

	runs callbacks on recycled threads instead of creating a new one per call
]=]
```

tags such as `@yields`, `@server`, `@client`, `@deprecated` and `@since` show up as badges, and
admonitions (`:::tip`, `:::info`, `:::caution`, `:::warning`, `:::danger`) become callouts:

```lua
--[=[
	:::tip Clean up
	disconnect the connection when you are done with it
	:::
]=]
```

run `just docs <Name>` to catch missing or broken docs before you push

## Releasing

CI runs the tests and checks the docs of every library on each push and pull request, and both
have to pass before a change is merged

once it is merged, `just release <Name> <major|minor|patch>` bumps the version, tests the library
and publishes it to ember. the site is rebuilt when CI passes on `main`, so a library shows up here
as soon as it has documented code and a `fumablox.toml`
